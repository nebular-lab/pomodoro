## 1. 概要

タスクを追加し、名前と色を変え、アーカイブする画面。使用中のタスクと、アーカイブ済みのタスクを、タブで切り替えて表示する。

## 2. クエリパラメータ

| パラメータ | 値 | 省略したとき | 用途 |
| --- | --- | --- | --- |
| `archived` | `true` | 「使用中」のタブを選ぶ | 選ぶタブと、一覧の条件（`GET /api/tasks` の `archived`）。`true` のとき「アーカイブ済み」のタブを選ぶ。`true` と完全に一致しない値のときは、省略したときと同じに扱う |

省略したときと同じに扱う値が URL に付いていたときは、初期表示時の処理で URL から取り除く（「5. 初期表示時の処理」の手順 1）。

## 5. 初期表示時の処理

1. URL クエリを整える（ブラウザの履歴を置き換える）。「2. クエリパラメータ」で省略したときと同じに扱う値の `archived` は消す。変えるところがなければ、何もしない。
2. URL クエリ `archived` が `true` なら No.8 を、なければ No.7 を、選んだ状態にする。
3. No.2、No.9、No.15、No.31、No.32、No.33 を非表示にする。
4. 一覧の位置に No.30 を表示する。
5. `GET /api/tasks`（operationId: `listTasks`）を呼ぶ。

   リクエスト

   | 場所 | パラメータ | 値 |
   | --- | --- | --- |
   | query | `archived` | URL クエリ `archived` が `true` なら `true`、なければ `false` |

   レスポンス

   | ステータス | 処理 |
   | --- | --- |
   | 200 | No.30 を非表示にする<br>`tasks` が 0 件なら No.31 を表示する<br>`tasks` が 1 件以上なら `tasks[]` を No.9 に入れて表示する |
   | 401 | ブラウザの保存領域のタイマーの状態を消して、SCR-001 ログインへ遷移する |
   | 422 | No.30 を非表示にする<br>MSG-005（v1: タスク）を No.32 に表示し、No.33 を表示する |
   | 上記以外 | No.30 を非表示にする<br>MSG-005（v1: タスク）を No.32 に表示し、No.33 を表示する |

### A1. 「追加」ボタン押下

1. No.2 を非表示にする。
2. バリデーションを行う。

   | No | 項目 | 条件 | メッセージ | 表示先 |
   | --- | --- | --- | --- | --- |
   | 3 | 新しいタスク | 必須（前後の空白を除いた値で確かめる。空白だけは未入力とみなす） | MSG-001（v1: タスク名） | No.4 |
   | 3 | 新しいタスク | 50 文字以内（前後の空白を除いた値で数える） | MSG-006（v1: タスク名、v2: 50） | No.4 |

3. エラーがあれば、No.4 に最初の 1 件を表示して終了する。なければ No.4 を非表示にする。
4. No.5 を非活性にする。
5. `POST /api/tasks`（operationId: `createTask`）を呼ぶ。

   リクエスト

   | 場所 | パラメータ | 値 |
   | --- | --- | --- |
   | body | `name` | No.3 の入力値 |

   レスポンス

   | ステータス | 処理 |
   | --- | --- |
   | 201 | No.3 を空にする<br>「使用中」のタブを選んでいて、No.9 か No.31 を表示しているとき、返ってきたタスクを No.9 の最後に足す（No.31 を表示していたら非表示にし、No.9 を表示する）<br>「使用中」のタブを選んでいて、一覧を読み込み中（No.30）か、読み込みのエラー（No.32）を表示しているときは、一覧を変えない<br>「アーカイブ済み」のタブを選んでいるときは、「使用中」のタブに切り替える（A2 を、「使用中」のタブを選んだものとして行う） |
   | 401 | ブラウザの保存領域のタイマーの状態を消して、SCR-001 ログインへ遷移する |
   | 422 | レスポンスの `code` に対応するメッセージを、下の「422 の表示先」のとおりに表示する（No.3 の値は残す） |
   | 上記以外 | MSG-004 を No.2 に表示する（No.3 の値は残す） |

   422 の表示先

   | `code` | メッセージ | 表示先 |
   | --- | --- | --- |
   | `TASK_NAME_REQUIRED` | MSG-001（v1: タスク名） | No.4 |
   | `TASK_NAME_TOO_LONG` | MSG-006（v1: タスク名、v2: 50） | No.4 |
   | 上記以外 | MSG-010 | No.2 |

6. 画面に残っているとき、No.5 の非活性を解除する。

### A2. タブの切り替え

1. すでに選んでいるタブを押したときは、何もせずに終了する。
2. No.2、No.15 を非表示にする。
3. 選んだタブを選択状態にする。
4. URL クエリの `archived` を、「アーカイブ済み」なら `true` に書き換え、「使用中」なら消す（ブラウザの履歴に追加する）。
5. 「5. 初期表示時の処理」の手順 3〜5 と同じく `GET /api/tasks` を呼ぶ（`archived` は手順 4 で書き換えた値になる）。

No.3 に入力途中の値があっても、そのまま残す。

### A3. タスクの色のボタン押下

1. 押した行の下に No.15 を表示しているとき、No.15 を非表示にして終了する。
2. ほかの行の下に No.15 を表示しているとき、それを非表示にする。
3. 押した行の下に No.15 を表示し、No.29 に、その行の、保存されている色を入れる。No.16〜No.27 と No.29 は、活性の状態で表示する。

### A4. タスク名の入力欄からフォーカスが外れる

1. No.11 の入力値（前後の空白を除く）が、その行の、保存されている名前と同じとき、その行の No.12 を非表示にして終了する。
2. No.2 を非表示にする。
3. バリデーションを行う。

   | No | 項目 | 条件 | メッセージ | 表示先 |
   | --- | --- | --- | --- | --- |
   | 11 | タスク名 | 必須（前後の空白を除いた値で確かめる。空白だけは未入力とみなす） | MSG-001（v1: タスク名） | その行の No.12 |
   | 11 | タスク名 | 50 文字以内（前後の空白を除いた値で数える） | MSG-006（v1: タスク名、v2: 50） | その行の No.12 |

4. エラーがあれば、その行の No.12 に最初の 1 件を表示して終了する（No.11 の値はそのまま残す。保存はしない）。なければ、その行の No.12 を非表示にする。
5. `PATCH /api/tasks/{taskId}`（operationId: `updateTask`）を呼ぶ。

   リクエスト

   | 場所 | パラメータ | 値 |
   | --- | --- | --- |
   | path | `taskId` | その行の `GET /api/tasks` の `tasks[].id` |
   | body | `name` | No.11 の入力値 |
   | body | `color` | 送らない |
   | body | `archived` | 送らない |

   レスポンス

   | ステータス | 処理 |
   | --- | --- |
   | 200 | その行の、保存されている名前を、返ってきた `name` にし、No.11 にも入れる |
   | 401 | ブラウザの保存領域のタイマーの状態を消して、SCR-001 ログインへ遷移する |
   | 404 | MSG-011 を No.2 に表示する（No.11 の値は残す。保存されている名前は変えない） |
   | 422 | レスポンスの `code` に対応するメッセージを、下の「422 の表示先」のとおりに表示する（No.11 の値は残す。保存されている名前は変えない） |
   | 上記以外 | MSG-004 を No.2 に表示する（No.11 の値は残す。保存されている名前は変えない） |

   422 の表示先

   | `code` | メッセージ | 表示先 |
   | --- | --- | --- |
   | `TASK_NAME_REQUIRED` | MSG-001（v1: タスク名） | その行の No.12 |
   | `TASK_NAME_TOO_LONG` | MSG-006（v1: タスク名、v2: 50） | その行の No.12 |
   | 上記以外 | MSG-010 | No.2 |

保存に失敗したあと、No.11 にもう一度フォーカスを入れて外すと、保存をやり直す（入力値が、保存されている名前と違うままなので）。

   リクエスト

   | 場所 | パラメータ | 値 |
   | --- | --- | --- |
   | path | `taskId` | その行の `GET /api/tasks` の `tasks[].id` |
   | body | `name` | 送らない |
   | body | `color` | 送らない |
   | body | `archived` | 固定値 `true` |

   レスポンス

   | ステータス | 処理 |
   | --- | --- |

### A6. 「アーカイブを解除」ボタン押下

1. A5 と同じ処理をする。違うのは、対象のボタンが No.14 であること、`archived` に固定値 `false` を送ること、タイマーの状態の「選択中のタスク」は変えないこと。

### A7. 既定の色のボタン押下

1. No.2 を非表示にする。
2. No.16〜No.27 と No.29 を非活性にする（No.29 で選んでいる値は残す）。
3. `PATCH /api/tasks/{taskId}`（operationId: `updateTask`）を呼ぶ。

   リクエスト

   | 場所 | パラメータ | 値 |
   | --- | --- | --- |
   | path | `taskId` | No.15 を表示している行の `GET /api/tasks` の `tasks[].id` |

   | body | `color` | 押したボタンの色（`#RRGGBB`） |
   | body | `archived` | 送らない |

   レスポンス

   | ステータス | 処理 |
   | --- | --- |
   | 200 | その行の、保存されている色を、返ってきた `color` にし、No.10 をその色にする<br>No.15 を非表示にする |

   | 422 | MSG-010 を No.2 に表示する（No.15 は表示したままにする。`code` による出し分けはしない） |

4. No.16〜No.27 と No.29 の非活性を解除する（No.15 を非表示にしたあとでも解除する）。

### A8. その他の色で、色を選び終える

1. A7 と同じ処理をする。違うのは、`color` に No.29 で選んだ色（`#RRGGBB`）を送ること。
